# 읽기 요약 앱 기획서 — 조사 · 계획 · UI/UX

> 작성일: 2026-11-17 · 플랫폼: iOS 네이티브(SwiftUI, iOS 26+) · 주 사용 기기: iPhone 13 mini
> 상태: M1~M4 구현 완료(2026-11-17). 만든 결과와 계획에서 달라진 점은 6.1에 있다.
> 숫자는 모두 2026-11-17에 Notion DB 전체(472장)와 본문 표본 20장을 읽기 전용으로 조회해 계산한 값이다.

## 1. 한 줄 정의

매일 새벽 4시에 Notion에 쌓이는 글 요약을, 아침에 한 손으로 훑어보고 궁금한 글만 원문으로 넘어가는 개인용 읽기 앱.

Notion 앱으로도 볼 수 있지만 DB를 열고 카드를 하나씩 여는 데 시간이 걸린다. 이 앱은 열자마자 오늘 요약이 보이고, 오프라인에서도 읽히고, 검색이 바로 되는 것이 목적이다.

용어

- **카드**: 요약된 글 1건. Notion 페이지 1개와 같다.
- **한줄요약**: 카드의 `한줄요약` 속성. 실제로는 한 문장(중앙값 82자)이다.
- **핵심**: 카드 본문의 불릿 5~6개.
- **날짜 묶음**: 같은 날 만들어진 카드들. 새벽 4시 실행 한 번이 하루 묶음이 된다.

## 2. 조사 결과

### 2.1 파이프라인이 만드는 것

`summarize_unread.py`가 FreshRSS의 안 읽은 글을 `claude -p`로 요약해 Notion DB "Reeder 읽기 요약"에 카드를 만든다.

| 위치 | 내용 |
| --- | --- |
| 속성 6개 | `제목`(title) · `날짜`(date, 원문 발행일) · `태그`(multi-select) · `출처`(text) · `링크`(url) · `한줄요약`(text) |
| 본문 블록 | 💡 callout(한줄요약과 같은 문장) → 불릿(핵심) → "원문 보기" 링크 문단. 표본 20장 모두 이 순서 |
| 만들어진 시각 | 페이지의 `created_time`. 속성에는 없지만 API 응답에 들어 있다 |

`날짜`는 원문 발행일이고 요약된 날이 아니다. 앱에서 "오늘 온 요약"을 가르는 기준은 `created_time`이어야 한다.

### 2.3 Notion API (이 DB에서 직접 확인)

| 항목 | 확인한 내용 |
| --- | --- |
| 버전 | 파이프라인은 `2022-06-28`, 최신은 `2026-03-11`. `2025-09-03`부터 DB 아래에 "데이터 소스"가 생겨 조회 경로가 `POST /v1/data_sources/{id}/query`로 바뀌었다. 옛 버전도 계속 동작하지만 DB에 데이터 소스를 하나 더 붙이면 조회가 실패한다 ([업그레이드 안내](https://developers.notion.com/docs/upgrade-guide-2025-09-03)). 이 DB는 최신 버전으로 목록·본문 조회가 모두 된다 |
| 목록 조회 | 100장에 약 226KB · 0.6초. 전체 472장은 5요청 · 약 1.1MB · 3초 |
| 바뀐 카드만 조회 | `last_edited_time` 필터 사용. 바뀐 것이 없으면 응답 172바이트 · 0.4초 |
| 본문(핵심) | 카드마다 `GET /v1/blocks/{id}/children` 1요청. 약 7.6KB · 0.4초. 여러 장을 한 번에 받는 방법은 없다 |
| 한도 | 연결(통합) 하나당 분당 180요청(Business·Enterprise 요금제는 600), 넘으면 429와 `Retry-After` ([문서](https://developers.notion.com/reference/request-limits)) |
| 오류 모양 | 틀린 토큰 401 `unauthorized`. DB가 없거나 통합에 연결되지 않았으면 404 `object_not_found` |
| 태그 색 | 데이터 소스 스키마와 카드 응답에 옵션 색 이름(blue, purple …)이 들어 있다 |

### 2.4 rss.gowoobro.com (FreshRSS)

- 피드 20개, 지금 안 읽은 글 0개. 파이프라인이 읽음 처리까지 정상으로 하고 있다.
- 요약은 여기에 없다. 요약은 Notion에만 있고, FreshRSS에는 원문이 있다.
- 로그인하지 않고 주소를 열어도 글 목록과 본문이 보인다. 익명 읽기가 허용된 상태다. (8장 확인 항목)
- 읽음 처리된 글의 본문도 남아 있다(최근 글 기준 1.5만~5.7만 자). 나중에 앱 안에서 원문을 보여 줄 재료가 된다.

## 3. 결정: 데이터와 구조

### 3.1 Notion에서 바로 읽는다

앱이 Notion API를 직접 호출한다. 서버를 새로 만들지 않고 파이프라인도 고치지 않는다. 지금까지 쌓인 472장이 그대로 보인다.

파이프라인이 요약을 JSON으로 서버에 따로 올리고 앱이 그것을 읽는 방식은 쓰지 않는다. 서버 배포, 인증, 기존 카드 이전이 필요한데 2.3의 수치로는 얻는 것이 없다.

앱은 최신 API 버전 `2026-03-11`과 데이터 소스 경로를 쓴다. 연결할 때 `GET /v1/databases/{id}`로 데이터 소스 ID를 한 번 찾아 저장한다. 파이프라인은 지금 버전 그대로 둔다.

### 3.2 동기화

1. 앱을 열면 기기에 저장된 카드로 바로 그린다. 네트워크를 기다리지 않는다.
2. 그 뒤 바뀐 카드만 받는다. 기준은 `last_edited_time`이 마지막 동기화 시각보다 뒤인 카드이고, 시각이 분 단위로 기록되므로 5분 여유를 둔다. 시점은 실행할 때, 30분 넘게 지나 앱으로 돌아왔을 때, 목록을 당겼을 때.
3. 핵심이 아직 없는 카드는 최신순으로 초당 2건씩 미리 받는다. 처음 설치하면 472건에 약 4분이 걸리지만 화면을 막지 않는다. 이후에는 하루 1~6건이다. 상세를 열었는데 아직 없으면 그 카드를 먼저 받는다.
4. Notion에서 지운 카드는 7일에 한 번 전체 ID를 대조해 지운다. 설정의 "전체 다시 받기"로도 할 수 있다.
5. 429를 받으면 `Retry-After`만큼 쉬고 이어서 받는다.

### 3.3 토큰

- 토큰은 기기의 키체인에만 둔다. 앱 번들과 저장소에는 넣지 않는다.
- 앱 전용 Notion 통합을 새로 만들어 "콘텐츠 읽기" 권한만 주고 이 DB에 연결하기를 권한다. 파이프라인 토큰은 페이지를 만들 수 있어서 폰에 둘 이유가 없고, 통합을 나누면 요청 한도도 따로 계산된다.
- **결정(2026-11-17): 통합을 새로 만들지 않고 파이프라인의 기존 토큰을 그대로 쓴다.** 앱은 읽는 요청만 보낸다(DB 조회, 목록 조회, 본문 블록 조회). 나중에 통합을 나누고 싶으면 설정의 "토큰 바꾸기"에서 토큰만 갈아 끼우면 되고, 받아 둔 내용은 그대로 남는다.
- 넣는 방법은 연결 화면(4.6)에 붙여넣기다. Debug 빌드는 실행 인자 `-notionToken`으로도 받아 키체인에 넣으므로, 설치 직후 인자를 붙여 한 번 실행하면 폰에서 붙여넣을 필요가 없다.

### 3.4 기기에 저장하는 것

| 무엇 | 어디 | 비고 |
| --- | --- | --- |
| 카드 목록 | Application Support의 JSON 파일 | 472장에 수백 KB |
| 핵심 | 같은 폴더의 JSON 파일 | 카드 ID와 `last_edited_time`으로 최신 여부 판단 |
| 저장한 글 | JSON 파일 (카드 ID, 저장 시각) | v1은 이 기기에만 |
| 설정, 마지막 방문·동기화 시각 | UserDefaults | 구조체는 항목마다 `decodeIfPresent` + 기본값 |
| 토큰, DB ID | 키체인 | |

태그와 출처 목록은 앱 코드에 고정하지 않고 받은 카드에서 뽑는다. 태그 색도 Notion이 주는 옵션 색을 쓴다.

## 4. UI/UX

### 4.1 원칙

1. **열면 바로 읽힌다.** 저장된 내용을 먼저 보여 주고 동기화는 뒤에서 한다. 처음 연결할 때 말고는 화면 전체를 가리는 로딩이 없다.
2. **목록만 훑어도 요약이 읽힌다.** 한줄요약을 자르지 않는다.
3. **한 손, 작은 화면.** 원문 보기, 다음 글, 검색, 필터는 전부 화면 아래에 둔다.
4. **관리할 것이 없다.** 안 읽은 개수도 읽음 처리도 없다. 새로 온 날에 점 하나만 찍는다.

### 4.2 화면 구성

```
연결(처음 한 번) ──▶ 타임라인 ──┬──▶ 상세 ──▶ 원문(앱 안 Safari)
                               └──▶ 설정
```

탭 바를 두지 않는다.

- 내용이 한 종류다. "오늘"과 "보관함"으로 나눠도 같은 목록의 앞부분과 전체일 뿐이다.
- "오늘" 탭은 사흘에 한 번은 비고, 평소에도 2장 안팎이다.
- 화면 안 검색은 오른쪽 아래 돋보기 버튼(아래 툴바)으로 두는 것이 기존 규칙인데, 탭 첫 화면에서는 탭 바와 자리가 겹친다.
- 375×812pt 화면에서 탭 바 높이만큼 본문이 더 보인다.

내비게이션 바는 숨기고(`.toolbar(.hidden, for: .navigationBar)`) 제목을 목록 첫 줄에 `.largeTitle.bold()`로 둔다. 스크롤한 내용은 상태 표시줄 밑에서 흐려진다(`.scrollEdgeEffectStyle(.soft, for: .top)`). 설정 버튼 하나 때문에 바를 살리지 않고, 버튼을 제목 줄 오른쪽에 둔다. 제목 위에는 여백을 두지 않고 상태 표시줄 바로 밑에서 시작한다. 그 위치에서는 멈춰 있을 때도 흐림 효과가 제목 윗부분을 덮으므로, 흐림은 스크롤을 시작한 뒤에만 켠다(`scrollEdgeEffectHidden`). 연결 화면의 제목도 같은 높이, 같은 왼쪽 시작점(16pt)이다.

> 처음에는 "설정 버튼이 있으니 바를 두고 시스템 큰 제목을 쓴다"로 정했으나, 버튼 하나뿐인 바가 사실상 빈 바여서 화면 상단 규칙에 어긋났다. 2026-11-17에 위와 같이 고쳤다.

**부제**는 상태에 따라 넷 중 하나다: "받아오는 중…" / "새 요약 3개" / "새 요약 없음" / "오프라인 · 11월 15일 04:10 기준".

**날짜 묶음**

- 카드가 만들어진 날(기기 시간대)로 묶는다. 머리글은 "오늘", "어제", "11월 13일 목요일"이고 올해가 아니면 연도를 붙인다. 오른쪽에 장 수를 적는다. 스크롤해도 머리글이 위에 붙어 있다.
- 날짜는 최신순, 같은 날 안에서는 발행일 최신순이다. 새 글이 앞에 오고 뒤늦게 들어온 옛 글이 뒤로 간다.
- 지난번 방문 뒤에 만들어진 날짜 묶음은 머리글 앞에 강조색 점을 찍는다. 앱을 닫고 30분 넘게 지나 다시 열면 지운다.
- 하루 10장이 넘으면 5장만 보여 주고 "나머지 35개 보기" 줄을 둔다. (화면에 보이는 개수 단위는 "개"로 통일했다: "3개", "새 요약 2개") 누르면 그 날만 펼친다. 필터나 검색 중에는 접지 않는다.

**카드 한 장**

- 출처 → 제목 → 한줄요약 → 태그 순서로 세로로 쌓는다. 13 mini에서 보통 8줄(약 190pt)이라 한 화면에 3장쯤 보이고, 평소 하루치는 한두 화면이다.
- 한줄요약은 줄 수를 제한하지 않는다. 가장 긴 200자가 9줄쯤이다.
- 출처 이름은 끝의 " - Medium"과 " RSS Feed"를 떼고 한 줄로 보여 준다. 넘치면 끝을 줄인다.
- 발행일이 요약된 날보다 7일 넘게 앞서면 출처 옆에 "3월 5일 글"(올해) 또는 "2020년 3월 글"(이전 해)을 적는다. 기술 글은 오래되면 내용이 달라져 있을 수 있어서다.

**동작**

| 동작 | 결과 |
| --- | --- |
| 카드 누르기 | 상세로 이동 |
| 왼쪽으로 밀기 | 원문 열기 |
| 오른쪽으로 밀기 | 저장 / 저장 해제 |
| 길게 누르기 | 저장 · 원문 보기 · 공유 · 요약 복사 |
| 목록 당기기 | 바뀐 카드 받기 |

### 4.4 상세

```
 ‹                                 🔖   ⋯      저장 · 더 보기
 토스 기술 블로그 · 2026년 10월 14일            출처 · 발행일
 Spark Connect on Kubernetes #2:               제목 (크게, 굵게)
 Operator로 만드는 Control Plane
 (인프라) (개발) (AI)                           태그

 ▍토스증권이 Kubernetes 위에서 다수의           한줄요약: 강조색 옅은 바탕
 ▍Spark Connect 서버를 안정적으로 운영하기…

 • 두 계층의 Operator로 Control Plane을 구성    핵심 5~6개: 본문 크기,
 • Blue-Green 교체로 서버를 무중단으로 바꿈       줄 간격 넉넉히
 • …

 AI가 요약한 내용이라 원문과 다를 수 있습니다.   작은 글씨

 [ 원문 보기 ]                      (∧) (∨)    아래 툴바
```

- 내비게이션 바는 제목 없이 `.inline`으로 둔다.
- **아래 툴바 왼쪽 "원문 보기"**가 이 화면의 주 버튼이다(`glassProminent`). 앱 안 Safari 시트로 연다.
- **아래 툴바 오른쪽 ∧ ∨**는 이전 글, 다음 글이다. 순서는 들어오기 전 목록 그대로이고(필터·검색 결과 포함) 처음과 끝에서는 흐려진다. 오늘 묶음의 첫 카드를 열고 ∨만 눌러 끝까지 읽을 수 있다. 넘기면 스크롤을 맨 위로 돌린다.
- 좌우로 넘기는 방식은 쓰지 않는다. 뒤로 가기 스와이프와 겹친다.
- **오른쪽 위**: 저장 토글, 더 보기 메뉴(공유 · 요약 복사 · Notion에서 열기). "요약 복사"는 제목, 한줄요약, 핵심, 링크를 글로 복사한다.
- 핵심을 아직 받지 못했으면 그 자리에 회색 줄 3개를 두었다가 받으면 바꾼다. 실패하면 "핵심을 불러오지 못했어요"와 다시 시도 버튼을 둔다.
- 본문 글자는 길게 눌러 선택하고 복사할 수 있다.
- 본문 블록은 callout과 불릿 말고도 문단, 번호 목록, 제목 블록을 글자로 읽어 보여 준다. Notion에서 카드에 메모를 덧붙여도 깨지지 않게 하기 위해서다.

### 4.5 필터 · 검색 · 저장

**필터** (왼쪽 아래 버튼을 누르면 메뉴)

```
 저장한 글만            ✓
 ─────────────
 태그                   ▸    전체 / 개발 437 / AI 313 / …
 출처                   ▸    전체 / Banksalad 104 / 토스 기술 블로그 74 / …
 ─────────────
 필터 지우기
```

- 태그와 출처는 각각 하나만 고른다. 많은 순으로 늘어놓고 장 수를 적는다.
- 필터가 걸리면 버튼이 강조색으로 채워지고, 목록 맨 위에 조건 칩("AI ✕")이 생긴다. 칩을 누르면 그 조건이 꺼진다.

**검색** (오른쪽 아래 돋보기, 누르면 검색창으로 펼쳐짐)

- 기기에 받은 카드에서 제목, 한줄요약, 출처, 태그, 핵심을 찾는다. 네트워크를 쓰지 않는다.
- 띄어 쓴 단어는 모두 들어 있어야 하고 대소문자를 가리지 않는다. 필터와 함께 걸린다.
- 구현은 `.searchable` + `.searchToolbarBehavior(.minimize)` + `DefaultToolbarItem(kind: .search, placement: .bottomBar)`.

**저장**

- 나중에 원문을 읽을 글에 다는 표시다. 목록에서 밀거나 상세의 북마크 버튼으로 켠다.
- v1은 이 기기에만 저장한다. Notion에 쓰지 않으므로 읽기 전용 토큰으로 충분하다.

### 4.6 연결 화면 (처음 한 번)

```
 Notion 연결
 요약이 쌓이는 Notion 데이터베이스를 읽어 옵니다.
 토큰은 이 기기의 키체인에만 저장됩니다.

 통합 토큰       [ ntn_…                ] 붙여넣기
 데이터베이스    [ 주소 또는 ID          ] 붙여넣기

 › 토큰은 어디서 만드나요?        누르면 3단계 안내가 펼쳐짐

 [ 연결 ]                         아래 툴바. 두 칸이 차야 눌림
```

- 데이터베이스 칸은 Notion 주소를 통째로 붙여도 ID 32자리를 뽑아 쓴다.
- "연결"을 누르면 DB를 읽어 속성 6개가 있는지 확인하고, 통과하면 첫 동기화를 한 뒤 타임라인으로 간다.

| 실패 | 안내 문구 |
| --- | --- |
| 401 | 토큰이 맞지 않아요. |
| 404 | 데이터베이스를 찾지 못했어요. Notion에서 DB의 ··· → 연결에 이 통합을 추가했는지 확인하세요. |
| 속성 없음 | '한줄요약' 속성이 없어요. (없는 속성 이름을 넣는다) |
| 네트워크 | 연결할 수 없어요. 잠시 뒤 다시 시도하세요. |

### 4.7 설정

하위 화면이므로 제목을 바 가운데에 둔다(`.inline`).

- **Notion**: DB 이름, 카드 수, 마지막 동기화 시각, 핵심 받은 수(412/472). 버튼은 "지금 동기화"와 "전체 다시 받기".
- **연결**: "토큰 바꾸기", "연결 끊기". 연결을 끊으면 키체인과 저장된 내용을 지우며, 지우기 전에 확인을 받는다.
- **정보**: 버전.

글자 크기와 화면 모드는 시스템 설정을 따르고 앱에 따로 두지 않는다.

### 4.8 상태별 화면

| 상황 | 보이는 것 |
| --- | --- |
| 첫 동기화 중 | 자리 표시 카드 5장, 부제 "받아오는 중…" |
| 평소 실행 | 저장된 카드가 바로 보이고 뒤에서 동기화. 새 카드는 목록 맨 위에 있을 때만 바로 끼워 넣고, 읽는 중이면 위치를 지킨다 |
| 오프라인, 동기화 실패 | 저장된 카드 그대로, 부제 "오프라인 · 11월 15일 04:10 기준". 경고창은 띄우지 않는다 |
| 토큰이 무효(401) | 목록 맨 위에 "Notion 연결을 확인해 주세요" 줄. 누르면 설정으로 |
| 카드 0장 | "아직 요약이 없어요" + "매일 새벽 4시에 쌓입니다" |
| 필터 결과 없음 | "조건에 맞는 글이 없어요" + "필터 지우기" 버튼 |
| 검색 결과 없음 | 시스템 검색 빈 화면(`ContentUnavailableView.search`) |
| 핵심이 없는 카드 | 한줄요약만 보이고 "핵심이 없는 글이에요". 원문 보기는 그대로 |

### 4.9 시각 디자인

색과 크기의 최종 값은 구현하면서 라이트·다크 스크린샷을 나란히 놓고 확정한다.

**목록 모양**: 테두리와 그림자가 없는 평면 목록(`.plain`)에 구분선만 둔다. 카드 모양으로 감싸면 좌우 32pt를 잃어 한 줄에 들어가는 글자가 줄고 카드가 길어진다.

**글자**: 전부 시스템 글자 스타일을 써서 시스템 글자 크기 설정을 따른다.

| 요소 | 스타일 | 색 |
| --- | --- | --- |
| 출처, 태그 | caption | 보조색 |
| 목록 제목 | headline (굵게) | 기본색 |
| 한줄요약 | subheadline, 줄 간격 약간 | 기본색. 보조색은 흰 바탕에서 대비가 낮아 본문에 쓰지 않는다 |
| 날짜 머리글 | title3 굵게 | 기본색, 장 수는 보조색 |
| 상세 제목 | title2 굵게 | 기본색 |
| 상세 한줄요약, 핵심 | body, 줄 간격 넉넉히 | 기본색 |

**강조색**: 형광펜을 닮은 주황. 형제 앱 "오늘 한장"의 파랑과 구분된다.

| 모드 | 값 | 대비 |
| --- | --- | --- |
| 라이트 | `#C2410C` | 흰 바탕에서 5.2:1 |
| 다크 | `#EA580C` | 검은 바탕에서 5.9:1, 그 위의 흰 글자 3.6:1 |

쓰는 곳은 주 버튼, 새로 온 날 점, 저장 표시, 필터가 걸린 버튼, 한줄요약 바탕(10% 농도)이다.

**태그 색**: Notion 옵션 색을 같은 이름의 시스템 색으로 옮긴다(blue, purple, red, green, orange, pink, brown, yellow). `default`와 `gray`는 회색이다. 목록에서는 색 점과 이름, 상세에서는 옅은 바탕의 캡슐로 보여 준다.

**아이콘**: 주황 그라데이션 바탕에 흰 종이 한 장. 종이에는 굵은 줄 하나(제목)와 점+줄 셋(핵심)이 있다. 기본·다크·틴티드 세 가지를 `digest_ios/tools/make_icon.py`로 만든다. 다크와 틴티드는 배경이 투명하고 틴티드는 회색조다.

**움직임**: 시스템 전환만 쓴다. 저장을 켜고 끌 때 가벼운 햅틱을 준다.

### 4.10 접근성

- 가장 큰 글자 크기에서도 요소를 세로로만 쌓아 잘리지 않게 한다.
- VoiceOver는 카드 한 장을 한 요소로 읽는다(출처, 제목, 요약, 태그). 저장과 원문 열기는 커스텀 액션으로 넣는다.
- 색만으로 구분하지 않는다. 태그는 이름을 함께 적고, 새로 온 날 점에는 "새로 온 요약" 레이블을 단다.


단계마다 빌드한 뒤 13 mini 시뮬레이터에서 라이트·다크 스크린샷을 나란히 놓고 확인하고, 연결된 iPhone에 설치한다.

**Debug 전용 실행 인자** (`#if DEBUG`, Release에는 영향 없음)

| 인자 | 동작 |
| --- | --- |
| `-notionToken <토큰>` `-notionDatabase <ID>` | 키체인에 넣고 연결 화면을 건너뛴다 |
| `-mockData YES` | 코드에 든 표본 카드로 실행한다(네트워크 없음). 스크린샷 비교용 |
| `-initialScreen detail` / `settings` / `connect` | 그 화면으로 바로 들어간다. `detail`은 첫 카드이고 `-openCard 3`으로 순서를 고른다 |
| `-filterTag AI` `-filterSource Banksalad` `-filterSaved YES` | 필터가 걸린 상태로 시작한다 |
| `-searchText 쿠버네티스` | 검색이 펼쳐진 상태로 시작한다 |
| `-newSinceDays 3` | 3일 전 이후에 온 요약을 "새로 온 요약"으로 본다 |
| `-scrollToDay 2026-11-07` (`-scrollAnchor bottom`) | 그 날짜 묶음이 맨 위(또는 맨 아래)에 오게 한다 |
| `-expandDays YES` | 몰린 날을 펼친 상태로 시작한다 |
| `-simulateNewCards YES` | 표본 데이터에서 2초 뒤 새 요약 2개가 도착한다 |
| `-connectToken <토큰>` `-connectDatabase <주소·ID>` `-connectSubmit YES` | 연결 화면 칸을 채우고 "연결"까지 누른다. `-connectHelp YES`는 안내를 펼친다 |
| `-replaceToken YES` / `-confirmDisconnect YES` | 설정에서 토큰 바꾸기 시트 / 연결 끊기 확인창을 띄운다 |
| `-offline YES` | 모든 요청이 "인터넷 연결 없음"으로 실패한다 |
| `-resetState YES` | 저장된 내용과 설정을 지우고 시작한다 |

Notion 응답을 카드로 바꾸는 부분, 날짜로 묶고 접는 규칙, 검색 매칭은 단위 테스트를 둔다.

### 6.1 구현 결과 (2026-11-17)

M1~M4를 모두 만들었다. 단위 테스트 30개가 통과하고, 단계마다 13 mini 시뮬레이터에서 라이트·다크 화면을 확인했으며, 연결된 iPhone 13 mini에 설치했다.

| 단계 | 기준 | 확인한 것 |
| --- | --- | --- |
| M1 | 실제 472장이 날짜별로 보이고, 네트워크를 끊어도 보인다 | 실제 DB 472장 표시. `-offline YES`로 다시 열어 저장된 카드와 "오프라인 · … 기준" 부제 확인 |
| M2 | 상세에서 ∨만 눌러 끝까지 읽는다 | 실제 카드의 상세 화면(요약 상자·핵심 6개·아래 툴바). 이전·다음 순서는 단위 테스트로 확인했고, ∨를 실제로 누르는 것은 폰에서 확인이 필요하다. 핵심은 최신 카드부터 초당 2장씩 미리 받는다(45초에 75장, 전부 최신순) |
| M3 | 11-07 묶음이 접히고, "쿠버네티스" 검색이 바로 나온다 | 11-07이 5개 + "나머지 35개 보기"로 접힘. "쿠버네티스 프로브"를 넣으면 맞는 카드만 바로 남는다. 태그·출처 필터와 칩 |
| M4 | 토큰 없이 설치해 연결부터 읽기까지 막힘이 없다 | 저장 내용을 지운 상태에서 주소(`?v=` 포함)를 넣어 연결 → 472장 표시. 틀린 토큰의 안내 문구, 설정, 토큰 바꾸기, 연결 끊기 확인창 |

계획에서 달라졌거나 더한 것:

- 화면의 개수 단위를 "개"로 통일했다.
- 아래쪽을 읽는 중에 새 요약이 오면 목록을 밀지 않고 위쪽에 "새 요약 N개" 버튼을 띄운다. 누르거나 맨 위로 돌아가면 끼워 넣는다(4.8 "읽는 중이면 위치를 지킨다").
- 연결할 때 속성이 있는지뿐 아니라 종류(`링크`가 URL인지 등)도 확인한다.
- 다른 DB로 연결을 바꾸면 받아 둔 내용과 저장 표시를 지우고, 토큰만 바꾸면 그대로 둔다.
- 검색은 제목·한줄요약·출처·태그에 더해, 이미 받아 둔 핵심 문장도 찾는다.
- 설정의 정보 묶음에 "저장한 글" 개수를 넣었다.
- 타임라인의 내비게이션 바를 숨기고 제목·부제·설정 버튼을 목록 첫 줄로 옮겼다(4.3). 스크롤하면 날짜 머리글이 상태 표시줄 바로 밑에 붙는다.

아직 손으로 확인하지 못한 것(시뮬레이터에서 탭·스와이프를 자동으로 할 수 없어서): 상세의 ∧∨와 저장 버튼, 줄을 미는 동작(저장·원문), 길게 눌러 뜨는 메뉴, 필터 메뉴 펼침, 공유 시트, 붙여넣기 버튼, 원문 시트 안의 실제 페이지 표시. 폰에서 한 번씩 눌러 보면 된다.

## 9. 조사하다 발견한 파이프라인 쪽 사항

앱 작업 범위는 아니다. 앱은 아래 경우를 모두 견디게 만든다.

- 피드를 새로 넣으면 그 피드의 지난 글이 전부 요약된다(11-07~08에 뱅크샐러드 74장). 발행일이 일정 기간을 넘은 글은 건너뛰는 옵션을 스크립트에 둘 수 있다.
- 요약 JSON 파싱에 실패하면 응답 원문 앞 200자가 한줄요약에 들어간다(1장). 한 번 다시 시도하거나 실패로 처리할 수 있다.
- `날짜`가 컨테이너 시간대(UTC)로 계산돼, 한국 시각 오전 9시 전에 발행된 글은 하루 이르게 기록된다.
- 같은 링크의 카드가 1건 중복돼 있다.
